# AtliQ Contract Risk Analyzer

A review assistant for a founder-led IT services company with no legal team. It reads every clause of an incoming contract, checks it against a register of what AtliQ has already promised, against how AtliQ negotiated similar clauses before, and against entity, country and paperwork rules, and returns a cited review brief with a suggested next step. **A person reviews, negotiates and signs. The assistant never signs, approves or sends anything.**

Built by Rahul for the Codebasics AI PM capstone. All data is synthetic. Not legal advice.

**Live prototype:** https://atliq-contract-risk-analyzer-teal.vercel.app (Vercel free tier, auto-deployed from `main`). Model: Claude Sonnet 5.

## What it does

1. **Header facts** are extracted from the contract into a fixed schema (parties, AtliQ entity, country, law, courts, data types, documents referenced, insurance, payment days).
2. **Rules, no AI** (`data/rules.json`, `lib/pipeline.mjs` → `applyRules`): the rule is fixed in code and reads the facts from step 1, which are shown for checking: entity vs country, governing law vs the entity's home law, regulated data types, documents the deal type needs, numeric gaps such as insurance. Every regulatory point is a flag to confirm with counsel.
3. **Register check**: the deal is compared with the confirmed obligations register (`data/register.json`, built once from the 17 signed contracts). Conflicts are reported only with both clauses quoted. Expired restrictions that would otherwise have applied are listed as checked, so the reviewer can see they were considered.
4. **Clause by clause**: every clause gets a type, a plain-English line, a verdict (fine / needs attention / conflict), the quoted text, and past positions from the negotiation history, shown as history, never policy.
5. **Mutuality**: clauses labelled mutual, and AtliQ's own paper, are checked for one-sidedness in both directions.
6. **Suggested next step**: sign, negotiate or escalate. A suggestion only; the reviewer confirms or overrides with a reason, and the override is recorded.

### Guardrails in code
- Every quote is matched back to the source text; unmatched quotes are flagged and counted (`verifyQuotes`).
- An output filter counts forbidden phrases such as "safe to sign".
- Every brief carries the label *"AI-generated draft review. Not legal advice. A person decides."*
- The app has no capability to send, sign or change a document. No email, no e-signature, no integrations.

## Run it

Requirements: Node 20+, an Anthropic API key.

```bash
npm install
echo ANTHROPIC_API_KEY=sk-ant-... > .env          # never commit this file
node scripts/build_contracts_index.mjs          # public/contracts.json for the picker
node scripts/build_register.mjs                 # one-time: extracts the register (measured $0.96 at list prices; resumable)
npm run test:golden                             # runs the 8 golden contracts (measured $0.09 to $0.19 per contract on Claude Sonnet 5, about $1.25 per run)
node scripts/dev_server.mjs                     # local test server on :3000 serving dist/ and /api/review (no extra tools)
npx vercel dev                                  # local site + /api/review (plain `vite` does not serve the API)
```

Deploy: push to GitHub with the Vercel project connected; set `ANTHROPIC_API_KEY` in the Vercel project's environment variables. `vercel.json` includes `data/**` in the function bundle and allows a 300-second run for long contracts.

Optional: `REVIEW_MODEL=<model id>` in the environment switches the model (default `claude-sonnet-5`).

## Layout

| Path | What |
|---|---|
| `api/review.js` | The one serverless function. Streams Server-Sent Events: progress, facts, rules, text, done. |
| `lib/pipeline.mjs` | Prompts, schemas, rules engine, quote verification, pricing. Shared by the API and the scripts. |
| `data/` | The synthetic dataset (unchanged from the capstone pack), `rules.json`, `register.json`, test results. |
| `scripts/` | `build_register.mjs`, `golden_test.mjs`, `build_contracts_index.mjs`. |
| `src/` | React page: Review, Obligations register, Golden tests, Evals vs PRD (the ten PRD eval dimensions against the stored golden run; `?tab=evals`), How it works. |

## Dataset notes

The dataset is the capstone pack as supplied: 15 incoming drafts, 17 signed contracts, negotiation notes, meeting notes, tracker, entity sheet and checklist. Nothing was added. `data/register.json` and `data/golden_results.json` are generated by this project.

## Measured on the prototype (list prices)

| | Value |
|---|---|
| Register build, one time | 17 contracts, 56 entries, 76k tokens in / 34k out, $0.96 (built on the first model, before the switch to Sonnet 5) |
| One review, Claude Sonnet 5 | 25k to 39k tokens in, 4k to 12k out, $0.09 to $0.19 (average $0.16), 41 to 110 seconds |
| Golden set | 8 of 8 scenarios pass on Sonnet 5, $1.25 per run. The first run on the earlier model scored 5 of 8: two reviews hit an output limit since raised, and one "failure" was the test's own expectation being wrong (BlueOrchid's property list includes Dubai and Muscat, so the Al Noor non-compete applies) |
| Quotes checked in code | 203 of 203 quotes in the final run matched the source word for word; 0 forbidden phrases. An earlier run flagged 3: a literal "not found" that was being counted as a quote (the verifier now ignores it), a paraphrase of the contract's wording, and a register entry quoted differently from the stored clause. Mismatches are shown as unverified in the brief, not dropped. |

The cost estimate made before the build assumed $0.15 per review. The register and the clause tables came out larger than estimated; the cost sheet was updated with the measured numbers and the $1 per review ceiling still holds.

## Known limits (prototype)

- No login. Role-based access is specified in the PRD, not built.
- No PDF upload; contracts are chosen from the dataset or pasted as text.
- No masking of names and rates before the model call, because the data is synthetic. The PRD requires it for real contracts.
- Precedent uses the negotiation notes in full (about 1,100 words) rather than vector search.
- Register entries are marked confirmed after the author's review; in production Karandeep confirms each one.
